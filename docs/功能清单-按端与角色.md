## 一、Web 管理后台

文档依据（附件1“Web 管理后台平台 / 系统管理后台”）：

> 管理员维护基础数据、账号、角色权限和系统参数，查看全部预约记录并进行紧急审批；查看日度/月度预约量、审批通过比例、通行记录、黑名单拦截台账、异常预警和审计日志；管理 IP 黑名单、同步任务及数据对接任务。

| 功能模块 | 功能点（文档原文归纳） | 文档依据 |

| 账号生命周期 | 人员删除后账号停用；重新添加人员时可恢复历史账号 | 用户管理模块 1 |

| 差异化规则 | 按临时访客、校友、学生家长、长期施工/合作访客配置差异化预约表单、办理流程和准入规则 | 用户管理模块 1 |
| 校内人员管理 | 学生、教职工、商户等各类校内人员信息管理；校内存量人员基础信息、辅导员与学生归属关系从数据中台对接获取、自动同步更新 | 用户管理模块 2；附件2 第4项 |

| 安全管理 | IP 黑名单管理；IP 限流与临时封禁参数；登录防护、权限校验、操作审计 | Web 管理后台；系统设置模块；权限与安全审计模块；附件2 第10项 |
| 对接管理 | 同步任务及数据对接任务管理；定时同步、手动触发、同步日志、失败重试、异常告警 | Web 管理后台；附件2 第4项 |

| 功能模块 | 功能点 | 文档依据 |

### 1.3 校内审核员（被访人 / 辅导员 / 班主任）

> 文档中的“审核员（含校内师生等）”不是单独角色，由被访的校内人员承担；通过 i 阳光 APP 或 PC 门户登录，依托统一身份认证开展审批。

| 审批场景 | 审批链路 | 文档依据 |
|---|---|---|
| 被访人是本校学生 | 访客提交 → 学生（被访人）审批 → 辅导员二次审批；两级全部通过后生效 | 审批流程模块 1） |
| 被访人是本校教职工 | 访客提交 → 教职工（被访人）审批，通过即生效 | 审批流程模块 2） |
| 被访人是食堂工作人员 | 访客提交 → 食堂工作人员（被访人）审批，通过即生效 | 审批流程模块 3） |
| 被访人是校内商户 | 访客提交 → 商户（被访人）审批，通过即生效 | 审批流程模块 4） |
| 被访人是附属中小学教职工 | 访客提交 → 中小学教职工（被访人）审批，通过即生效 | 审批流程模块 5） |
| 被访人是附属中小学学生 | 访客提交时填写对应班主任工号 → 该班主任审批，通过即生效 | 审批流程模块 6） |

| 通用功能 | 说明 | 文档依据 |
|---|---|---|
| 审批操作 | 审批通过/驳回，填写审批意见，审批结果通知 | 审批流程模块 |
| 关系数据 | 学生与辅导员的对应管理关系从数据中台获取、存储、展示、更新 | 审批流程模块 1） |
| 登录方式 | i 阳光 APP 或 PC 门户，依托统一身份认证 | 用户管理模块 4 校内人员 |

## 六、原文依据（关键句）

1. 用户管理模块：“系统管理员完成审核员（含校内师生等）、保安、商户/食堂人员账号增删改、角色分配和权限设置……商户、食堂人员账号与手机号绑定，人员删除后账号停用，重新添加时可恢复历史账号。”
2. 用户管理模块：“建设校内人员管理模块，支持学生、教职工、商户等各类校内人员信息管理；校内存量人员基础信息、辅导员与学生归属关系等业务数据，统一从数据中台对接获取、自动同步更新。”
3. 预约处理模块：“保卫处管理员直录模式……部门发起审批模式：开放权限给二级学院、机关部处指定经办人，由经办人上传名单发起批量预约，流转至保卫处管理员审批。”
4. 审批流程模块：“支持单人一级审批、保卫安保二次复核、白名单免审自动通行、24 小时未处理自动驳回和批量通过/驳回……支持审批意见、紧急审批和审批结果通知。”
5. 车主查询模块：“授权保安或指定查询人员在 H5 端输入车牌号查询当天或最新有效预约信息，返回访客姓名、手机号、车牌、来访及离访时间；无权限用户屏蔽查询入口并禁止访问查询数据。”

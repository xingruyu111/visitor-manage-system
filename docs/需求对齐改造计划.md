# 需求对齐改造计划（以采购文档 附件1/附件2 为唯一依据）

> 旧需求文档（`F:\smart-campus\.claude\doc\智慧校园访客管理系统需求文档.md`）已过时，不再参考。
> 本文档记录当前实现与该采购文档的差距，以及按依赖排序的改造步骤。

## 一、目标模型（严格按文档）

### 1. 单校系统
- 文档全文无“多校/校区/超级管理员”，`vst_*` 的 `school_id` 仅保留为兼容字段，业务上恒为 1。
- 不再做学校管理、超管选校、跨校数据范围。

### 2. 角色（文档口径）

| 角色 | 说明 | 现有映射 |
|---|---|---|
| 系统管理员 | 账号、角色、权限、访客档案/类型/黑名单 | 原 SUPER + ADMIN 合并为 `SYSTEM_ADMIN` |
| 保卫处管理员 | 审批、名单、门闸、统计 | 新增 `SECURITY_ADMIN` |
| 审核员（校内师生） | 被访人审批 | 保留 `TEACHER` / `STUDENT` 作为身份，不再单独做“审核员”账号 |
| 保安 | 扫码核验、车主查询 | `GUARD` |
| 商户 / 食堂人员 | 独立账号、对应审批流 | `MERCHANT` / `CANTEEN` |
| 二级学院/机关部处经办人 | 批量发起预约 | 新增 `DEPT_OPERATOR` |
| 访客 | 预约、凭证 | `VISITOR` |

### 3. 审批（文档明确要求）
- 单人一级审批（被访人）
- **保卫安保二次复核**（启用 SECURITY 节点，不再默认跳过）
- 白名单免审自动通行
- 24 小时未处理自动驳回
- **批量通过 / 批量驳回**
- 大学生本人 + 辅导员两级
- 教师、实验学校师生、商户、食堂人员按对应流程

### 4. 预约
- 差异化表单：普通 / 校友 / 学生家长 / 长期施工合作
- 校友按月有效期、家长固定时段
- 两种模式：保卫处直录、部门发起审批

### 5. 通行
- 凭证含有效期 + 通行次数（已实现）
- 门闸/停车场双向接口：下发权限、过期拦截、黑名单车辆同步（当前 Noop，待接）
- 入校/离校记录、离线核销

### 6. 名单
- 人员 / 机动车 / 电动自行车三类（已实现）
- 黑名单生效/失效/到期自动解除（已实现）
- 人工提前解除
- 白名单 Excel 导入、外系统双向同步

### 7. 其它
- 车主查询 H5（保安输车牌查预约）
- 微信授权登录
- 统一身份认证、统一待办/消息
- 历史数据迁移

## 三、原则

- 先改模型（P1/P2），再补功能（P3+），避免在错误角色模型上继续堆功能。
- 每阶段保持 `mvn verify` 通过（行覆盖 ≥90%、分支 ≥65%）。
- 前端菜单与权限跟角色模型同步调整，不再出现“超管选校”。
